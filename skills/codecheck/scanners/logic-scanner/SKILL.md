# Logic Scanner — 代码逻辑变更分析

## 定位

本 scanner 专注于**深度分析代码修改的逻辑影响**，系统化地发现所有逻辑问题。不同于常规代码审查，重点关注：逻辑影响范围分析、逻辑一致性检查、状态转换验证、边界条件分析、业务规则验证。

**Pattern 引用声明**：本 scanner 加载以下 pattern 文件作为检查规则来源：
- [`patterns/logic-correctness.md`](../../patterns/logic-correctness.md) — LOG-001~012
- [`patterns/memory-safety.md`](../../patterns/memory-safety.md) — MEM-001~005（边界条件交叉验证）
- [`patterns/concurrency.md`](../../patterns/concurrency.md) — CONC-001~004（并发逻辑）
- [`patterns/error-handling.md`](../../patterns/error-handling.md) — ERR-001~006（错误处理逻辑）

```
│  第二层：逻辑分析 (Logic Analysis)               │
│  - 控制流分析                                    │

├─────────────────────────────────────────────────┤

```

## 分析维度

| 维度 | 检查内容 | 问题类型 | Pattern |
|------|----------|----------|---------|
| **控制流** | 分支、循环、条件判断 | 死代码、不可达代码、逻辑矛盾 | LOG-001~003 |
| **数据流** | 变量定义、赋值、使用 | 未初始化、数据污染、类型不匹配 | LOG-004~005, MEM-005 |
| **状态机** | 状态转换、转换条件 | 非法转换、状态不一致、死锁 | LOG-006~008 |
| **边界条件** | 数组边界、空值、极值 | 越界、空指针、溢出 | LOG-012, MEM-001~004 |

| **并发控制** | 锁、原子操作、竞态 | 死锁、竞态条件、数据竞争 | CONC-001~004 |

## 工作流

### Step 1: 变更识别与分类

识别变更类型：
- **类型 1: 控制流变更** — 新增/修改/删除条件分支
- **类型 2: 数据流变更** — 替换计算逻辑
- **类型 3: 状态转换变更** — 修改状态转换目标
- **类型 4: 函数签名变更** — 新增/删除参数
- **类型 5: 错误处理变更** — 新增/修改错误处理

**影响范围识别**：
- 直接影响：被修改的函数及其调用者、被修改的成员变量及其访问者、被修改的状态及其转换逻辑
- 间接影响：依赖修改函数返回值的代码、依赖修改状态的条件分支、调用链上的所有上层函数
- 可能影响：接口兼容性边界、性能边界、资源使用边界、并发安全边界

### Step 2: 执行逻辑分析

按 [`patterns/logic-correctness.md`](../../patterns/logic-correctness.md) 逐项扫描：

**控制流**（LOG-001~003）：
- 死代码：永不为真条件、return 后代码、重复条件
- 逻辑矛盾：互斥条件同时为真、冗余条件、条件覆盖矛盾
- 条件覆盖完整性：枚举类型完整性、switch-case 分支完整性、if-else 链完整性

**数据流**（LOG-004~005）：
- 未初始化变量：所有路径初始化检查
- 数据污染：外部数据来源识别、sink points 验证、sanitization 验证
- 类型安全：有符号/无符号比较、枚举值有效性、指针类型转换

**状态机**（LOG-006~008）：
- 非法状态转换：构建状态转换图，验证所有转换合法性
- 状态不一致：识别所有表示状态的相关变量，验证更新一致性
- 状态机死锁：检查强连通分量，验证是否存在无法到达终态的循环，检查超时机制

**边界条件**（LOG-012, MEM-001~004）：
- 数组越界：索引范围验证、循环边界检查、缓冲区大小验证
- 空指针：解引用前验证、函数返回值验证
- 整数溢出：算术运算验证、边界值检查

**错误处理**（LOG-009, ERR-001~006）：
- 错误路径完整性：所有可能失败操作、错误码传递、错误日志记录
- 资源管理：资源释放配对、错误路径释放、RAII 使用

**并发控制**（CONC-001~004）：
- 死锁预防：锁顺序一致性、循环等待检测、超时机制
- 竞态条件：共享变量保护、原子操作、同步机制
- 数据竞争：访问同步、内存序验证、读写锁使用

**业务规则**（LOG-010~011）：
- 不变性维护：识别不变性、验证操作后不变性、构造函数建立
- 契约遵守：前置条件验证、后置条件保证、异常安全性

### Step 3: 影响评估

- 直接影响：被修改函数行为改变
- 间接影响：所有调用方、依赖状态的条件分支
- 风险评估：数据一致性 / 线程安全 / 状态机完整性

## 严重等级

| 等级 | 说明 | 是否阻塞上库 |
|------|------|-------------|
| 🔴 致命 | 影响系统正确性/安全性（非法状态转换、死锁、内存泄漏） | ✅ 是 |
| 🟠 严重 | 可能导致问题（竞态条件、错误路径遗漏） | ✅ 是 |
| 🟡 警告 | 不影响基本功能（冗余代码、不完整错误处理） | ⚠️ 视情况 |
| 🟢 建议 | 改进代码质量（代码风格、性能优化） | ❌ 否 |

映射到统一等级：🔴→P0、🟠→P1、🟡→P2、🟢→P3。
